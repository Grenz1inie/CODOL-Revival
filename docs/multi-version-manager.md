# 多版本管理器

本次实现以网页选择本机游戏目录为入口。版本列表由仓库维护；只有版本配置与已核验的客户端指纹同时匹配、且对应实现已接入，才允许启动和修改玩家数据。

## 接口与测试边界

| 接口 | 必须覆盖的行为 | 不代表的结果 |
| --- | --- | --- |
| 版本识别 | 中文/空格路径；两个版本文件一致、缺一、冲突、损坏；目录或EXE缺失；未知版本；已知未接入版本；EXE不匹配 | 对局可玩 |
| 目录选择与保存 | 原生目录选择取消；有效选择持久化；无效选择清除旧的可用状态；运行中拒绝切换；重启重新核验；独立实例数据路径 | 玩家存档跨版本兼容 |
| 控制接口 | 未匹配时所有游戏/数据写操作拒绝；匹配后按能力开放；选择与操作串行；既有同源与输入校验保留 | 浏览器按钮状态本身足以保护服务端 |
| 版本适配入口 | 选择决定代码、启动参数、模拟服务器与数据目录；错误版本不得回退到3.3.3.3；停止使用运行会话的身份 | 新版本已有模拟服实现 |
| 网页 | 未选择/识别中/匹配/未支持/失败；版本列表；按钮禁用与恢复；取消不清空选择；账号随实例刷新；中英文和窄屏 | 游戏内人工验收 |

采用逐项失败测试、最小实现、定向通过；完成后集中运行一次完整测试和前端构建。现有游戏协议与Rust模拟行为不在本次变更范围。

## 阶段

1. 版本列表、只读识别和本机选择持久化。
2. 将3.3.3.3代码及模拟服务器归入版本目录，接入统一控制入口、实例路径和启动检查。
3. 网页目录选择、版本列表与能力门控；集中回归、实际网页检查、文档和分阶段本地提交。

实现只开放已经接入的3.3.3.3；2.6.9.7及3.19.26.22作为已知但未接入版本展示。首期同时运行一个游戏实例。选择目录不修改游戏文件、证书、hosts或防火墙。
