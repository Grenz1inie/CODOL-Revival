# 多版本管理器

本次实现以网页选择本机游戏目录为入口。版本列表由仓库维护；只有版本配置与已核验的客户端指纹同时匹配、且对应实现已接入，才允许启动和修改玩家数据。

## 接口与测试边界

| 接口 | 必须覆盖的行为 | 不代表的结果 |
| --- | --- | --- |
| 版本识别 | 中文/空格路径；两个版本文件一致、缺一、冲突、损坏；目录或EXE缺失；未知版本；已知未接入版本；EXE不匹配 | 对局可玩 |
| 目录选择与保存 | 原生目录选择取消；有效选择持久化；无效选择清除旧的可用状态；运行中拒绝切换；重启重新核验；独立实例数据路径 | 玩家存档跨版本兼容 |
| 控制接口 | 未匹配时所有游戏/数据写操作拒绝；匹配后按能力开放；选择与操作串行；既有同源与输入校验保留 | 浏览器按钮状态本身足以保护服务端 |
| 版本适配入口 | 选择决定代码、启动参数、模拟服务器与数据目录；错误版本不得回退到3.3.3.3；停止使用运行会话的身份 | 新版本已有模拟服实现 |
| 网页 | 未选择/识别中/匹配/未支持/失败；版本列表；按钮禁用与恢复；取消不清空选择；账号随实例刷新；中英文和窄屏 | 游戏内人工验收 |

采用逐项失败测试、最小实现、定向通过；完成后集中运行一次完整测试和前端构建。现有游戏协议与Rust模拟行为不在本次变更范围。

## 阶段

1. 版本列表、只读识别和本机选择持久化。
2. 将3.3.3.3代码及模拟服务器归入版本目录，接入统一控制入口、实例路径和启动检查。
3. 网页目录选择、版本列表与能力门控；集中回归、实际网页检查、文档和分阶段本地提交。

首期接入3.3.3.3；后续已接入3.19.26.22的启动与本地服务，见[专属说明](wiki/v3_19_26_22-startup.md)。2.6.9.7仅收录。同时运行一个游戏实例。选择目录不修改游戏文件、证书、hosts或防火墙。

## 实际目录与接入方式

当前版本源码位于 `games/codol/versions/v3_3_3_3/`：`server/`包含Python服务，`server/native/match-server/`包含Rust模拟服；`resources/definitions/`保存静态数据；`reverse/tools/`保存资源工具、探针和冻结对照；`reverse/recovered-code/`保存原始恢复代码。为减少不必要改动，既有协议文件先保留名称和内部组织，避免目录迁移同时改写协议。

新增版本先在 `games/codol/versions.json` 添加版本条目，`adapter: null`表示仅收录、不开放操作。完成该版本的适配器和测试后，填写独立模块名及已核验EXE指纹。适配器接口为 `settings/set_settings`、`profiles/inventory/mutate`、`environment`与`capabilities`；等级上限也由版本能力提供。管理器不导入固定版本的档案代码。

版本文件确有差异时，条目用 `version_files` 明确各来源的实测原文；3.19的TCLS为3.19.26.22、IIPS为V1.2.1.13。这个映射仍受EXE指纹约束，不允许任意忽略冲突。适配器可提供 `command_timeout`，用于首次复制大体积客户端；共用默认启动入口给控制API保留相应等待时间。

持久化配置仅保存本机安装选择。实例ID按版本与规范化安装路径生成；模拟服务器命令行明确携带实例数据目录，进程控制同时核对源码路径与实例路径。单次运行仍只支持一个游戏实例，端口不自动改写。

首次选择原安装时，将旧玩家数据与备份复制到临时目录，全部成功后发布为实例目录，再保存选择。原数据保留；已有实例不会重新导入。原始大体积研究证据和历史快照仍按原路径保留，避免改变证据内容。生产数据只使用实例目录。

管理器启动检查与游戏检查分开：没有游戏也能打开管理器；只有游戏启动时检查该版本的端点、证书和运行前提。版本列表的“已接入”表示控制逻辑已接入，不等于该版本全部玩法已恢复。3.3.3.3的游戏内验收范围沿用现有Wiki。
