## 已确认的交付边界

- 3.3首次启动自动备份并配置所选游戏目录中的`dwauth.ini`、`stun.ini`、`cacert.pem`；保留原CA并追加本实例CA。EXE、系统证书、hosts和防火墙不在修改范围。
- 3.19也必须摆脱外部启动包。验收输入为仓库源码、匹配的原游戏及公开工具链；不能将旧包里的EXE/DLL、转储、快照或资源补丁重新打包当作完成。
- 3.19继续使用隔离游戏副本；原游戏保持不变。现有玩家进度、实例隔离、启停和首次硬件提示等待行为须保留。
- 公开工具链和依赖仍有明确的安装、构建步骤；“可重建”不等于本轮增加自动下载安装器。首次准备与只读检查分开，已有可用产物不要求重新安装编译器。
- 本轮围绕部署和准备，不增加地图、玩法或AI行为。正在进行的3.19 Rust/核弹小镇工作作为已有工程衔接，不另写一套对局实现，也不把未接入代码当成已可替换旧组件。

## 测试先行与阶段验收

1. **先复现3.3初始化与诊断失败**：空runtime；先选择后准备；已有`instance.json`但证书缺失；有效/过期/损坏/不匹配证书；原CA保留且追加一次；配置写入失败可恢复；非匹配EXE和只读检查零写入；HTTP保留stdout/stderr具体原因。每个行为红 → 最小实现 → 绿。
2. **3.3脚本集成**：直接服务与网页路径均先准备后启动；失败不启动；重复运行不更换有效证书、不覆盖存档、不重编有效地图。仅改fixture不足以证明链路，补一次真实准备入口测试。
3. **3.19去依赖小步闭环**：先移除认证标准表/已有定义的旧包依赖；再逐个建立启动桥接和数据生成契约。以当前客户端消费者/已保存原生证据验证，不能仅做自我编码解码；替代某个组件后再移除对应生产依赖。
4. **首次部署验收**：从Git可交付文件创建独立目录，清空继承的作者路径环境，只提供声明的工具链及匹配原游戏。初始无runtime/research/旧启动包/旧存档；所有运行输入必须落在允许根目录内。验证缺件、中断重试、中文/空格路径及原游戏/玩家数据保护。若3.19仍有路径限制，应明确检查并记录，不能误称任意路径可用。
5. **运行验收分层**：先验证真实TLS客户端信任、认证响应、资源内容与自有进程生命周期；再由用户确认首次提示、大厅和现有对局行为。端口就绪、HTTP200或导出成功均不足以代替游戏画面与操作。
6. **控制验证成本**：每个新增行为定向TDD；阶段结束集中跑受影响套件，构建按输入复用。最终做一次隔离部署验证；不因阶段性提交重复全套，不用本地预装旧组件掩盖失败。报告源码完成、服务采用与实机验收各自状态。
