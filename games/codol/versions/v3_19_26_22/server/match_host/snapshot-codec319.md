# 3.19 快照编码

`snapshot_codec319.py` 替代 `snapshot319_live.exe`，由 `LiveSim.payload` 直接调用。`client/match.py` 在对局开始时生成初始快照，字节与历史 Seatown 落地快照一致，不再读取作者的预制文件。默认配装、运动字段及已有实体/客户端标记保持原协议。

`snapshot_fields319.json` 的27张字段表来自原游戏 EXE，记录了SHA256和各表VA。用 `reverse/tools/export_snapshot_fields319.py <原游戏EXE>` 可只读核验；加 `--output <文件>` 可重建定义。玩家246字段、客户端87字段、24类实体的63字段及185个事件参数位宽均逐项核验。`living` 和 `allowed` 是本地对局初始化及输入约束，不是游戏资产。

固定回归样本位于 `tests/fixtures/snapshot319-reference.json`，来源记录了旧编码器SHA256。每例独立启动旧编码器采样，避免旧进程的弹药覆盖状态污染下一例；测试和生产执行均不需要旧程序。样本覆盖全部24个实体类型、移动/角度、武器状态、弹药、事件、位宽边界、顺序错误、初始快照及非法输入。测试同时验证空实例中的实时编码与切换武器不会启动子进程。

验证范围为字节协议兼容和现有对局服务生命周期；没有代替真实客户端的人工游玩验收。
