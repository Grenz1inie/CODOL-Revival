REA 6.4.0 成功加载同一 EXE 的历史快照。一次四函数 `batch_decompile` 查询触发客户端 300 秒超时，结束快照中的对应记录为 provider 超时，四项失败、零项成功；没有确认新的 REA 反编译结果或缓存命中。没有循环重试全量分析。

新增函数使用已安装的 Ghidra 12.1.4 与 JDK 21，通过 `-readOnly -deleteProject -noanalysis`、明确入口和 `ExportFocusedFunctions.java` 导出。七个成功批次分别输出 35、8、45、10、3、3、2 个函数，共 106 份定向观察；入口、正文、指令、CALL 位置和工具版本保存在 `evidence/focused/round2-*.json`。临时项目均使用本目录下被忽略的 `work-projects/`，只读导入在结束时丢弃。首次点前缀临时目录被 Ghidra 拒绝，改用该目录后完成；没有把失败运行计入函数总数。

阶段二还复用 5 份同哈希历史 REA 伪代码作为变体，因此新增伪代码份数大于该阶段 Ghidra 输出数。两阶段均保留此前主伪代码文件的字节哈希；新增结果以变体收录，不改写原始变量、语句和警告。
